# Test Cases

Документ подготовлен на основе отчёта по практической работе №11 и отражает ключевые сценарии для frontend-части проекта.

## TC-01 Авторизация пользователя, позитивный сценарий

- Предусловие: пользователь зарегистрирован.
- Шаги: открыть страницу входа, ввести корректный email и пароль, нажать `Войти`.
- Ожидаемый результат: выполнен вход, открыт личный кабинет согласно роли.

## TC-02 Авторизация пользователя, негативный сценарий

- Предусловие: пользователь зарегистрирован.
- Шаги: открыть страницу входа, ввести корректный email и неверный пароль, нажать `Войти`.
- Ожидаемый результат: отображается сообщение `Неверный логин или пароль`.

## TC-03 Создание турнира

- Предусловие: пользователь вошёл как организатор.
- Шаги: открыть раздел турниров, заполнить обязательные поля, сохранить.
- Ожидаемый результат: новый турнир отображается в списке.

## TC-04 Ввод результата матча

- Предусловие: пользователь вошёл как судья.
- Шаги: открыть форму результата, указать счёт и событие матча, сохранить.
- Ожидаемый результат: результат сохранён, статус `Требует подтверждения`.

## TC-05 Автоматический расчёт турнирной таблицы

- Предусловие: есть подтверждённые результаты матчей.
- Шаги: открыть раздел турнирной таблицы и проверить позиции команд.
- Ожидаемый результат: таблица отображается в корректном порядке.

## TC-06 Генерация протокола матча в PDF

- Предусловие: матч завершён и подтверждён.
- Шаги: открыть матч, нажать на генерацию протокола.
- Ожидаемый результат: PDF-файл скачивается и содержит данные матча.

## TC-07 Экспорт турнирной таблицы в Excel

- Предусловие: турнир активен, есть данные таблицы.
- Шаги: открыть таблицу, нажать экспорт.
- Ожидаемый результат: скачан файл `.xlsx`, структура сохранена.

## TC-08 Подача заявки на турнир

- Предусловие: пользователь вошёл как тренер, турнир открыт для заявок.
- Шаги: открыть турнир, заполнить форму заявки, отправить.
- Ожидаемый результат: заявка отправлена, организатор видит уведомление или новую запись.

## TC-09 Валидация минуты гола, негативный сценарий

- Предусловие: открыта форма ввода результата матча.
- Шаги: ввести минуту `150`, сохранить.
- Ожидаемый результат: показана ошибка валидации.

## TC-10 Проверка прав доступа

- Предусловие: пользователь вошёл как зритель.
- Шаги: открыть карточку матча, попытаться изменить результат.
- Ожидаемый результат: редактирование недоступно.

## TC-11 Адаптивность интерфейса

- Предусловие: система доступна через браузер.
- Шаги: открыть приложение при ширине `320px`, проверить формы, кнопки и навигацию.
- Ожидаемый результат: интерфейс остаётся рабочим и читаемым.

## TC-12 Время загрузки основных страниц

- Предусловие: локальный или тестовый стенд доступен.
- Шаги: открыть страницы турниров, матчей и таблицы, замерить время загрузки.
- Ожидаемый результат: время загрузки не превышает `2 секунд`.

## TC-13 Резервное копирование БД

- Предусловие: backend и БД работают больше суток.
- Шаги: проверить логи резервного копирования.
- Ожидаемый результат: бэкап создан в заданное окно времени.

## TC-14 Хэширование паролей

- Предусловие: в БД есть пользователи.
- Шаги: проверить формат хранения поля `password`.
- Ожидаемый результат: пароли хранятся в хэшированном виде.

## TC-15 Локализация интерфейса

- Предусловие: система работает с локалью `ru-RU`.
- Шаги: открыть любую страницу и проверить язык интерфейса и формат даты.
- Ожидаемый результат: интерфейс русскоязычный, даты отображаются корректно.

## Примечание

На текущем этапе frontend полностью покрывает сценарии TC-01, TC-02, TC-03, TC-04, TC-08, TC-09, TC-10 и частично покрывает TC-11 и TC-15. Для TC-01, TC-02, TC-03, TC-04, TC-08 и TC-10 добавлена стартовая автоматизация через Selenium WebDriver в `tests/ui/`. Сценарии, завязанные на backend, экспорт, PDF и безопасность, требуют интеграции серверной части.
